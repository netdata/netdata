## Overview

Monitor browser Web Vitals, document and application-view traffic, JavaScript errors and resource timing.

The Faro browser SDK sends measurements to the configured RUM receiver. Netdata aggregates accepted observations over a sliding window, retains sampled investigation history locally, and optionally exports event logs and browser traces through OTLP/gRPC. Native charts, session timelines and errors need no OTLP receiver. Country-only geolocation is the default; approximate city markers require explicit opt-in and remain live-only. Frustration heuristics are disabled by default and do not establish intent or causality. Application-provided user IDs remain original application-controlled identifiers, not anonymous values. URL/path and targeted text normalization are limited transformations, not general anonymization or consent handling. Event logs add searchable custom-event attributes and optional console messages; tracing adds sampled browser request spans. Both are disabled by default and have independent destinations.

This collector is only supported on the following platforms:

- Linux
- macOS

This collector supports collecting metrics from multiple instances of this integration.

The Netdata service needs write access to its DEM state directory. Configured TLS and GeoIP files must be readable by the Netdata service account.

### Default Behavior

#### Auto-Detection

Sites are explicitly configured; websites are not discovered automatically.

#### Limits

Breakdown charts show current-window top groups. Missing browser observations cannot be reconstructed, and
capacity loss suppresses affected percentiles and window counts. Duplicate detection is best effort across a bounded
30-minute retention period; capacity pressure or restart can shorten it. Quality alerts require at least 30
observations for that metric and complete local measurement state. Quiet traffic alone does not trigger an alert.

History uses one plugin-wide journal file-age and committed-byte retention target in dem.conf, including disabled
sites. Whole archives expire; the active file is protected, so the size target is not a hard disk ceiling.
Export/history queues count records dropped under backpressure. Detail sampling applies to native history and enabled
event logs and traces. Problem overrides retain available recent native context with its original attribution, then
current and future detail while the session remains tracked. Earlier logs and spans are not exported retrospectively;
complete sessions or traces are not guaranteed. Export acceptance does not guarantee durable storage.


#### Performance Impact

Resource usage depends on accepted browser traffic and the configured measurement window. Optional OTLP export and investigation history add network and local disk work.

## Setup


### Prerequisites

#### Install the DEM plugin

DEM is experimental and opt-in. Build Netdata with `-DENABLE_PLUGIN_DEM=ON`, or use `--enable-plugin-dem` with the source installer. Install the resulting DEM plugin package.

#### Configure the receiver and site

Configure the canonical receiver in `dem/receiver.conf`, then add one job per website in `dem/rum.conf`. The native configuration UI exposes the receiver as a single object and sites as independently managed jobs.

#### Install the browser snippet

Add `<script async src="https://rum.example.org/rum/shop.js"></script>` to the website, replacing the configured public receiver URL and site key. The receiver serves the pinned SDK too; allow its script and connection URLs in the website Content Security Policy. Proxy the entire RUM path, including SDK assets and collect requests. A script-only redirect is insufficient.

#### Optional searchable event logs

Event logs and tracing are optional and disabled by default. Enable an OTLP/gRPC receiver separately. In the receiving Netdata node's Logs tab, select `otel-logs` and the `netdata-rum` service. Filter the time range, `resource.attributes.rum.site` and `attributes.session.id`; inspect `attributes.event.attr.<key>` for custom-event attributes and `attributes.console.level` with the message body for console messages. Netdata log access requires Cloud sign-in. Console errors are logs; uncaught exceptions and unhandled rejections remain native RUM errors. Event data is sampled and independently retained by the destination.

#### Optional browser tracing

To follow a request into backend services, instrument those services, accept browser trace context, allow trace headers in cross-origin CORS, coordinate sampling and send both sides to the same tracing system. Browser spans alone show browser requests, not a complete backend trace. For an external receiver, look up a copied trace ID in that system. Netdata receiver selection and direct UI navigation are part of the later frontend integration.

#### Customize alerts

Stock health templates evaluate complete LCP, INP and CLS populations with at least 30 observations. Quiet traffic alone has no stock alert. Customize thresholds or disable alerts through normal Netdata health configuration; use the `_collect_plugin=dem` and `_collect_job` chart labels for site-specific policies.

Send browser spans to your backend tracing receiver without enabling event logs. Provide the secret and configure backend instrumentation, context propagation, CORS and compatible sampling separately.

<details open><summary>Examples</summary>

      propagate_to: [https://api.example.org]
      destination:

</details>

## Metrics

Metrics grouped by *scope*.

The scope defines the instance that the metric belongs to. An instance is uniquely identified by a set of labels.

All charts remain on this Agent. Native job identity scopes site charts; display_name is optional metadata.
The window uses receiver arrival time. Each Web Vital contributes its latest report per document experience;
percentiles cannot be averaged across times or groups. Population charts show retained observations and ratings.
No observations means no percentile. Capacity loss makes affected percentiles and counts unavailable; lost_reports
is retained loss evidence, not a denominator or an exact count of missing observations in the window.

Document views count initial activations and back-forward cache restores. Application views count explicit route
occurrences separately. Observed sessions are distinct browser session identities seen in the window, not concurrent
users. JavaScript errors are events; errors divided by document views is not a failure percentage. Breakdowns use
current-window top groups plus a pooled other bucket; page Functions expose all retained document-entry groups.

The event-log (rum.otlp) and browser-span (rum.spans) charts and their loss alerts exist only while their respective
feature is enabled. sent counts records accepted by the receiver; errors counts records whose attempted delivery
failed or was rejected; dropped counts local queue or shutdown loss. Acceptance does not guarantee queryability
or durable storage. A timeout can have an unknown delivery outcome. Disablement and sampling do not count as loss.

## Live Data

Use these process-wide Functions through the Netdata Agent or Cloud to inspect RUM setup, live activity and retained investigation history. Invoke their public rum-* names; filter by site where supported.

### RUM Sites

Inspect site setup, sampling, receiver availability and recent activity to diagnose missing browser data.

| Aspect | Description |
|:-------|:------------|
| Name | `Rum-sites` |
| Require Cloud | no |
| Performance | Reads bounded local activity snapshots without contacting the monitored website. |
| Security | Results can include page paths, browser metadata, user identifiers, error messages and stack traces. Restrict access to authorized operators. |
| Availability | Available while dem.plugin is running; activity comes from admitted site jobs. |

#### Prerequisites

No additional configuration is required.

#### Parameters

This function has no parameters.

#### Returns

## Troubleshooting

### Other Problems

#### No browser measurements

Open `rum-sites` for receiver availability, collection policy and last accepted payload or rejected-origin observations. Missing traffic alone is not failure. In the website browser Network panel, follow the script request, SDK request and collect POST; check console CSP and Netdata RUM errors. POST 202 means accepted, 204 means intentional bot or disabled-collection exclusion, 400 invalid payload, 403 origin rejection, 404 missing site runtime or incorrect proxy path, 413 size rejection and 429 rate limiting. For 404, check native job state and the request path. A fresh session can still be sampled out; explicitly select 100% collection for a deterministic eligible-session check. Receipt does not prove human traffic, retained history or export delivery.

#### Missing exported events or spans

Check that the required signal is enabled and its receiver accepts OTLP/gRPC at the configured explicit http or https URL and port. Verify Bearer authentication, TLS trust and paired client certificate/key files. The event and span charts distinguish receiver-accepted records, failed or rejected delivery, and local queue/shutdown loss. A timeout may have an unknown delivery outcome; zero traffic proves neither failure nor success. Receiver failures do not stop native history.
