# Lighthouse Desktop Audit

## Overview

Monitor desktop lab performance for a web page with Lighthouse. Inspect the performance category score, individual lab timings, layout shift and audit execution outcomes.

Audits the configured HTTP or HTTPS page using the Lighthouse desktop preset and sandboxed Chromium at the native job interval. Configuration Test validates preparation without running an audit. Lab measurements describe this browser attempt and are not field Core Web Vitals.

This collector is only supported on the following platforms:

- Linux

This collector supports collecting metrics from multiple instances of this integration.

| Permission | Needed when |
|:--|:--|
| Execute the prepared Node runtime and sandboxed Chromium | Every browser attempt |
| Write to the DEM state directory | Retaining history and optional captures |


### Default Behavior

#### Auto-Detection

Jobs require explicit configuration; no websites or scripts are discovered automatically.

#### Limits

Missing scores or timings produce measurement gaps; a measured zero remains zero. Running and waiting attempts do not refresh the prior observation, which becomes stale after two collection intervals. HTML reports are disabled unless requested. No stock performance-score threshold alert is configured.

#### Performance Impact

Each attempt starts a fresh browser and consumes CPU, memory and target website requests. Increasing update_every reduces frequency. Jobs share one browser admission slot, so concurrent due jobs can wait. Optional captures consume local disk space.

## Setup


### Prerequisites

#### Set up the browser runtime

Browser runtime delivery is experimental; released bundles and automatic manifest installation are not
provided. Supply a trusted runtime manifest and its matching bundle before enabling browser monitors.
Run Chromium with its sandbox enabled as the unprivileged Netdata service account on Linux amd64 or arm64.
Managed mode prepares the exact runtime when a browser monitor is enabled, using an administrator-installed
runtime manifest. For offline setup, install the trusted manifest and import its matching archive, or select
`runtime.mode: preloaded` in `dem.conf` with the final `preload_path` produced by `dem.plugin runtime preload`.
Both modes require the trusted manifest and its matching bundle. Preloads stay outside automatic cleanup;
stop every consumer before replacing or removing them. Separately installed runtime components are unsupported.

Run `dem.plugin runtime status` to inspect preparation and `dem.plugin runtime qualify` as the service
account to check a local sandboxed browser run. Follow the
[DEM runtime setup guide](https://github.com/netdata/netdata/blob/master/src/go/plugin/dem/README.md#runtime-setup-and-retirement)
for manifests, downloads, offline imports, retention and protected preloads. Restart the plugin after changing
runtime configuration.

### Retained synthetic captures

Invoke `synthetics-artifacts` to find retained screenshot and report sets, newest publication first, even after run history expires or a monitor is disabled or deleted. Each set contains one run's captures. The shared default allowance is seven days and 2 GiB, preferring each monitor's newest eligible capture. Age and size pressure can still remove it; this is not complete incident history or a hard disk cap. A later Lighthouse report may displace that monitor's earlier poor-score report. Journey recovery without a screenshot leaves its previous failure capture eligible. Disabled or deleted monitors keep the same preference; renamed monitors form separate groups.

| Aspect | Description |
|:-------|:------------|
| Name | `Synthetics-artifacts` |
| Require Cloud | no |
| Performance | Reads local capture metadata and file sizes without reading capture contents or starting a browser. |
| Security | Requires member-equivalent access. Exposes monitor identities and capture metadata, not capture contents. |
| Availability | Available while dem.plugin is running, independently of active journey or Lighthouse jobs and retained run history. Captures can expire under age or size limits. |

#### Prerequisites

No additional configuration is required.

## Troubleshooting

### Other Problems

#### No conclusive observations

Inspect native job status for unavailable dependencies and plugin logs for runtime preparation errors, waiting attempts or execution inability. Open the latest retained run for errors and actual failure phases. Missing measurements are gaps; stale, inconclusive and cancelled observations are not recovery.
