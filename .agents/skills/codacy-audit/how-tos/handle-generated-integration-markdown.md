# How-to: handle Codacy findings in generated integration Markdown

## When to use

Use this when Codacy reports markdownlint findings in files matching
`**/integrations/*.md`, especially rules covering inline HTML, heading spacing,
code-block spacing, or image alternative text.

## Establish ownership first

Generated integration pages contain this metadata banner:

```text
message: "DO NOT EDIT THIS FILE DIRECTLY, IT IS GENERATED BY THE ... metadata.yaml FILE"
```

`integrations/gen_docs_integrations.py` writes these pages beside their source
`metadata.yaml` files. A hand edit is therefore not a durable fix: the next
generation run overwrites it.

Confirm a reported file is generator-owned:

```bash
head -12 path/to/integrations/example.md
rg -n 'write_to_file|clean_and_write|markdownlint-disable' \
  integrations/gen_docs_integrations.py
```

## Classify the findings

Fetch the PR issue dump, then count only added findings by file and rule without
printing `commitInfo`:

```bash
.agents/skills/codacy-audit/scripts/pr-issues.sh <PR> --by file

DUMP="$(ls -1t .local/audits/codacy/pr-<PR>-*.json | head -1)"
jq -r '
  .data[]
  | select(.deltaType == "Added")
  | [.commitIssue.filePath, .commitIssue.patternInfo.id]
  | @tsv
' "$DUMP" |
  awk -F '\t' '{ files[$1]++; rules[$2]++ }
    END {
      print "FILES"
      for (item in files) print files[item], item
      print "RULES"
      for (item in rules) print rules[item], item
    }'
```

Treat `commitInfo` as sensitive operational metadata. Do not copy contributor
names or email addresses into a SOW, skill, comment, commit, or PR description.

## Apply the repository boundary

The repository excludes generator-owned integration pages in `.codacy.yml`:

```yaml
exclude_paths:
  - "**/integrations/*.md"
```

This boundary does **not** exempt:

- source `metadata.yaml`;
- `integrations/gen_docs_integrations.py`;
- integration templates;
- ordinary hand-authored Markdown; or
- generated-doc and Learn-ingestion checks.

Do not add per-file markdownlint directives to generated pages. For a finding in
hand-authored Markdown, fix the source or use the narrowest justified
file-local rule suppression.

## Validate

Run the local analyzer and verify the excluded pages do not appear:

```bash
.agents/skills/codacy-audit/scripts/analyze-local.sh --tool markdownlint

DUMP="$(ls -1t .local/audits/codacy/local-markdownlint-*.json | head -1)"
jq empty "$DUMP"
jq -r '
  .[]
  | .Issue.filename? // .filePath? // empty
' "$DUMP" |
  rg '/integrations/.*\.md$'
```

The final `rg` should return no paths. Also run the normal integration
generation and Learn/documentation checks so the analyzer exclusion does not
replace source-boundary validation.

## How I figured this out

Files read:

- `../../integrations-lifecycle/artifacts-and-banners.md`
- `.codacy.yml`
- `integrations/gen_docs_integrations.py`
- representative generated collector integration pages
- the Codacy PR issue dump under `.local/audits/codacy/`

Commands run:

- `.agents/skills/codacy-audit/scripts/pr-issues.sh <PR> --by file`
- the `jq` and `awk` classification pipeline above
- `find src -path '*/integrations/*.md'`
- `.agents/skills/codacy-audit/scripts/analyze-local.sh --tool markdownlint`
