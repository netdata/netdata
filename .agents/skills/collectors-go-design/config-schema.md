# config_schema.json: The Operator's Form

`config_schema.json` is what an operator sees when they add or edit a job in the Netdata UI (DynCfg). The agent serves
the file verbatim and validates nothing against it; the UI renders it as a form and validates client-side. Every
sentence in it is operator-facing product text, not developer documentation.

Renderer contract (what the UI honors, how each channel renders, defaults, tabs, validation, secrets):
`src/plugins.d/DYNCFG.md`, section "JSON Schema for Configuration UI". Read it once; this file assumes it. Design-time
questions (which options exist, which mode is the default, strictness versus the collector's `validate()`) are in
`operator-surface.md`; this file is about writing the form well once those are decided.

Scope: every hand-written schema on this renderer: `go.d/collector/*/config_schema.json`, `go.d/discovery/sdext/*.json`,
`scripts.d/collector/*/config_schema.json`, `agent/secrets/secretstore/backends/*/config_schema.json`,
`framework/vnodes/config_schema.json`. ibm.d schemas are generated by `docgen`; fix the generator, not the output.
`framework/charttpl/config_schema.json` is not a form: it validates `charts.yaml` and follows its own rules.

## 1. Shape

- The file MUST be `{"jsonSchema": {...}, "uiSchema": {...}}`. A bare JSON Schema renders an empty form.
- `jsonSchema` MUST declare `"$schema": "http://json-schema.org/draft-07/schema#"`, `"type": "object"`, and a `title`
  naming the collector (`<Product> collector configuration.`, the fleet's pattern). A title copy-pasted from another
  collector is the first defect the operator sees.
- `uiSchema` mirrors `jsonSchema.properties` by key. A `uiSchema` entry whose key is not a property is silently
  ignored; keep the two in step when renaming. Nothing else belongs at the top level (no `uiOptions`; the UI does not
  read it).
- Property names are the YAML keys the operator types in a config file. Never invent a UI-only key.

## 2. The Four Text Channels

Each property has up to four texts. They have distinct jobs; do not use one to do another's.

- `title` (the label): REQUIRED on every visible property. A short noun phrase in sentence case, no trailing period,
  meaningful out of context (`Detection retry`, not `Retry`; `SNMP version`, not `Version`).
- `description` (the always-visible explanation): REQUIRED on every visible property, including objects and arrays.
  - One or two plain sentences that state the unit and what the default does; ends with a period.
  - Markdown only for inline code and links; no headings, lists, or line breaks (it renders as one paragraph).
- `ui:help` (depth on demand, in the info tooltip): OPTIONAL.
  - Use it only when there is more to say than the description: examples, formats, mode comparison, consequences,
    prerequisites.
  - Markdown, paragraphs separated by `\n\n`.
  - MUST NOT restate the description and MUST NOT be the only text on a field.
- `ui:placeholder` (an example value, greyed inside an empty input): OPTIONAL on any input that can be left empty.
  - An example in the field's exact format: `5m`, `postgres://user:${env:PG_PASSWORD}@localhost:5432/db`, `production`,
    `1000`.
  - Never an instruction sentence, and never on a field whose non-empty `default` already fills it (the placeholder
    would be invisible).

Voice, for every channel:

- Write for the operator filling the form, in the terms of the monitored system. Engine vocabulary (ticks, eligibility,
  journal, state machine, descriptor) MUST NOT appear; say what the setting changes for them.
- Name the unit in the description whenever a number has one: `in seconds`, `in bytes`, `per collection interval`.
- When the option is optional, say what happens when it is left empty ("Leave empty to use the AWS SDK endpoint.").
- When a value is referenced from another field, say where it is defined ("Name of a credential source defined on
  the Credentials tab.").
- Booleans: the title states what ON does (`Reject redirects`, not `Not follow redirects`).
- A description that only repeats the title (`Access key ID` / "Access key ID.") is a missing description.
- Markdown line breaks: a single `\n` renders as a space. In `ui:help` use `\n\n` between paragraphs, `-` lists, and
  fenced code for examples. Check the sql collector's `dsn` help as the pattern for a long, structured help.

## 3. Layout

- Tabs: use `"ui:flavour": "tabs"` when the properties fall into more than one concern (connection, what to collect,
  limits, labels, virtual node). Each tab is one concern, named after the config key or the operator's word for it
  (`Credentials`, `Targets`, `Rules`, `Limits`, `Virtual Node`), never after the implementation.
- Tab order is the order the operator fills the form: how to connect, what to collect, how much, where it appears.
  A tab that references names defined on another tab comes AFTER that tab.
- Field order inside a tab follows the object's property order in `jsonSchema` (after `ui:order`), not the order of
  names in `fields`; reorder the properties to reorder the form.
- Every top-level property, including a property a `dependencies` branch reveals, MUST be listed on exactly one tab,
  listed in `ui:options.rest`, or hidden. A property missing from all of them is unreachable in the UI and still
  submitted with its default.
- Tab titles MUST equal the `group` values in `metadata.yaml` (first segment before ` / `): the doc table and the form
  use one vocabulary. The `Tab / Subgroup` form exists because a tab can only group whole top-level properties, so a
  doc group that refines a nested concern (query timing, tag filters) cannot be its own tab. Call `collecttest.AssertConfigSchemaMatchesMetadata` from the collector's tests: a tabbed
  collector whose options or descriptions you change MUST opt in (a mechanical fleet sweep is not such a change); a
  schema without tabs cannot opt in until the helper handles the flat layout. Derive groups from the collector's own
  keys; do not copy a neighbour's tab list.
- Objects (sections) MUST carry `title` and `description` like any field: the section header is the first thing the
  operator reads. Optional advanced sections MAY set `"ui:collapsible": true`.
- Arrays of objects: set `"ui:listFlavour": "list"` (tabs mode labels every item `Rule N`); give the item schema a
  `title`; use `ui:order` on the item when the natural reading order differs from the JSON key order.
- Hidden (`"ui:widget": "hidden"`): only for options the collector supports but operators almost never set from the
  UI (for example the shared HTTP block's `body`, `method`, `force_http2`, `bearer_token_file`). An option the
  collector ignores MUST be removed from `Config`, the schema, and the docs, not hidden. A credential MUST NOT be
  hidden: `ui:widget` takes one value, so a hidden field cannot also be masked and its value shows in the YAML preview.
- A documented option (present in `metadata.yaml`) MUST be visible: the doc points the operator at a tab.

## 4. Types, Widgets, Constraints

- Keep the declared type equal to the Go field's accepted values. Optional objects and arrays are
  `["object", "null"]` / `["array", "null"]` (a YAML key with no value decodes to nil). Scalars stay single-typed.
- Enums: 2 to 5 values render as `"ui:widget": "radio"` with `"ui:options": {"inline": true}`; longer lists stay a
  select. Display labels come from `ui:options.enumNames` (the JSON Schema `enumNames` keyword is ignored). Avoid `0`,
  `false`, and `""` as enum values.
- Multi-line text (queries, request bodies, templates) uses `"ui:widget": "textarea"`, with `"ui:options": {"rows": N}`
  when 2 rows are too few.
- Durations are strings in Netdata duration syntax (`30s`, `5m`); give a placeholder. Numbers carry `minimum`
  (and `maximum` where the collector clamps); the UI enforces them live and blocks the save.
- `default` in the schema MUST equal the collector's constructor default; the form materializes every default into the
  submitted job. An option whose omission drives runtime precedence ("unset means inherit") MUST NOT carry a `default`.
- `required` lists only what the collector rejects when absent. A required property with a `default` is fine: the
  default satisfies it.
- Optional arrays MUST NOT declare `minItems`; the form would create an item the operator cannot delete. Express
  "non-empty when present" in `validate()`.
- Free key/value maps (labels, headers) are `"type": "object", "additionalProperties": {"type": "string"}`;
  `patternProperties` alone renders without an add button.

## 5. Conditional Sections

Use a discriminator plus `dependencies` for mutually exclusive configurations (modes, credential types):

```json
"properties": {
  "mode": {"title": "Mode", "description": "How ...", "type": "string", "enum": ["filters", "query"], "default": "filters"}
},
"dependencies": {
  "mode": {
    "oneOf": [
      {"title": "Filters", "properties": {"mode": {"const": "filters"}, "mode_filters": {"title": "...", "description": "...", "type": "object", "properties": {}}}},
      {"title": "Query", "properties": {"mode": {"const": "query"}, "mode_query": {"title": "...", "description": "...", "type": "object", "properties": {}}}}
    ]
  }
}
```

- The discriminator is a radio; its `ui:help` compares the modes (when to choose which).
- Branch section keys are `<discriminator>_<value>`; each branch carries its own `required`.
- A branch key MUST NOT also be a plain sibling property (it would render for every mode).
- With tabs, branch keys MUST be listed on a tab (they render only while their mode is selected); an unlisted branch
  key is dropped like any other property.
- Prefer top-level dependencies: the UI drops inactive-branch data only for top-level discriminators.
- Do not use property-level `oneOf`/`anyOf` for alternatives; the UI renders a branch selector whose first option
  cannot be selected reliably.

## 6. Secrets

- `"ui:widget": "password"` MUST be set on every property whose value is credential material: passwords, API keys,
  tokens, client secrets, private keys and passphrases given as values, SNMP communities and USM keys, and DSN/URL
  fields that accept embedded credentials (`user:password@host`). It masks the input and is the only signal that
  redacts the live YAML preview (`format: "password"` masks the input only).
- A free key/value map (`headers`, `labels`) cannot be redacted: its values carry no widget. When a map may hold a
  token, its description MUST tell the operator to use secret indirection (`${env:...}`).
- `proxy_url` and other `*_url` fields are identities to the rule test and MUST NOT be masked; route proxy credentials
  through `proxy_username`/`proxy_password` or `${env:...}`, never into the URL.
- It MUST NOT be set on usernames, file paths (`tls_key`, `bearer_token_file`), or URLs without credentials.
  Masking them hides nothing and stops the operator from reading back what they typed.
- `sensitive: true` in `jsonSchema` is read by nothing; do not write it.
- Placeholders and help examples for secrets show indirection (`${env:AWS_SECRET_ACCESS_KEY}`,
  `${file:/run/secrets/token}`) or an obviously synthetic value; never a realistic credential, account ID, or hostname
  (root `AGENTS.md`, "Sensitive Data In Durable Artifacts").

## 7. Standard Options

Use this wording for these options so the fleet reads alike; adapt the parts in angle brackets and add at most one
collector-specific sentence. Most collectors still carry older wordings; do not copy a neighbour.

```json
"update_every": {
  "title": "Update every",
  "description": "Data collection interval, in seconds.",
  "type": "integer",
  "minimum": 1,
  "default": 1
},
"autodetection_retry": {
  "title": "Detection retry",
  "description": "How often to retry the initial connection when the job fails to start, in seconds. Zero disables retries.",
  "type": "integer",
  "minimum": 0,
  "default": <n>
},
"timeout": {
  "title": "Timeout",
  "description": "<HTTP request | Connection and read/write | Command execution | Query> timeout, in seconds.",
  "type": "number",
  "minimum": <min>,
  "default": <n>
},
"url": {
  "title": "URL",
  "description": "URL of the <product> <status page | API endpoint>.",
  "type": "string",
  "format": "uri"
},
"username": {"title": "Username", "description": "Username for HTTP basic authentication.", "type": "string"},
"password": {"title": "Password", "description": "Password for HTTP basic authentication.", "type": "string"},
"vnode": {
  "title": "Virtual node",
  "description": "Associates this job with a [Virtual Node](https://learn.netdata.cloud/docs/netdata-agent/configuration/organize-systems-metrics-and-alerts#virtual-nodes).",
  "type": "string"
}
```

Matching `uiSchema` entries:

```json
"url": {"ui:placeholder": "<http://127.0.0.1:port/path>"},
"password": {"ui:widget": "password"},
"vnode": {
  "ui:placeholder": "<example-vnode-name>",
  "ui:help": "Charts of this job appear under the Virtual Node instead of this host. Define the Virtual Node in `vnodes.conf` first, then enter its name here."
}
```

`timeout` for the shared HTTP client is `HTTP request timeout, in seconds.`; for sockets `Connection and read/write
timeout, in seconds.`; for external commands `Command execution timeout, in seconds.`; for databases `Query timeout, in
seconds.`.

## 8. Alignment With metadata.yaml

- Option `description` in `metadata.yaml` (`setup.configuration.options.list[].description`) MUST equal the schema
  `description` for the same option; the doc table and the form are two views of one sentence. Depth that only the
  form needs goes in `ui:help`; depth that only the doc needs goes in `detailed_description`.
- `group` MUST equal the tab title (section 3); `default_value` MUST equal the schema `default`; `required` MUST match
  the schema `required` list.
- `collecttest.AssertConfigSchemaMatchesMetadata(t, "config_schema.json", "metadata.yaml")` checks tabs and
  descriptions in both directions: every documented option exists in the schema with the same description, and every
  visible top-level property is documented. Nested option names resolve through `properties`, `dependencies`
  branches, `allOf`, `$ref`, and array items written as `rules[].query.period`; keys of a free map
  (`additionalProperties`) are not documented as options. The call is opt-in because most collectors predate the
  alignment rule and would fail it today; `cloudwatch`, `ceph`, `s3check`, and `azure_monitor` are the worked examples.
- The stock `.conf` and the generated integration page are the other two views; `integrations-lifecycle/consistency.md`
  owns their mechanics.

## 9. Repo-Wide Rule Tests

`src/go/plugin/go.d/collector/config_schema_test.go` runs over every schema in scope. The tests are rules that fail on
a wrong schema; they never restate a file, and a failure is fixed in the schema, not by editing the test.

| Test | Rule |
|---|---|
| `TestConfigSchemasHaveTheFormShape` | wrapper, draft-07, top-level title |
| `TestConfigSchemasReachEveryProperty` | every property on one tab, in `rest`, or hidden |
| `TestConfigSchemasUseOnlyRenderedUIKeys` | only rendered `ui:*` keys, options, widgets |
| `TestConfigSchemasDescribeEveryVisibleProperty` | title and description everywhere; help adds, never repeats |
| `TestConfigSchemasMaskOnlySecrets` | password widget on credentials only; no `sensitive` flag |
| `TestConfigSchemasDoNotMaterializeOptionalArrays` | no `minItems` on optional arrays |
| `TestConfigSchemasDoNotDeclareBranchKeysAsProperties` | branch keys are not sibling properties |

The file also asserts that its glob list covers every `config_schema*.json` under `src/go/plugin` except the ibm.d
generated schemas and `framework/charttpl`, so a new schema outside the list fails the build.

Per-collector tests: opt into `AssertConfigSchemaMatchesMetadata`; test `validate()` by mutating a valid `Config`.
Do not write tests that restate the schema (`operator-surface.md`, section 5).

## 10. Review Checklist

1. Open the form in your head tab by tab: can an operator who knows the monitored product, but not Netdata's
   internals, fill every field from its title and description alone?
2. Every visible property has a title and a one-paragraph description; help adds, never repeats.
3. Tabs equal metadata groups; every property is reachable; order follows the filling sequence.
4. Secrets masked, usernames and paths not; no realistic credentials anywhere.
5. Defaults equal the constructor; no `default` on precedence-driven options; no `minItems` on optional arrays.
6. Standard options use the section 7 wording.
7. `go test ./collector/ -run TestConfigSchemas` and the collector's own tests pass.
